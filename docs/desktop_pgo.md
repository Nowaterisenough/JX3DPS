# 桌面批处理的 GCC Release PGO

PGO 使用实际战斗的执行计数帮助 GCC 决定如何内联函数、排列代码和优化常走的分支。桌面构建将 profile 应用到 `batch_worker.cpp`，两种心法的模拟器、伤害归约和八项属性收益都在这个编译单元实例化。普通构建默认使用 `JX3DPS_DESKTOP_PGO=OFF`。

在具备桌面构建依赖的环境，从仓库根目录运行以下命令。脚本使用 Python 3.8+、Ninja、CMake 和 `g++`，沿用项目的 Qt 6.12 桌面工具链。

```sh
python tools/desktop_pgo.py
```

脚本在 `.cache/desktop-pgo-release` 中构建 `JX3DPSDesktop`。它先启用 `GENERATE`，清理该编译单元旧的 `.gcda`，再启动同一个桌面可执行文件的无界面训练入口。训练覆盖太虚默认、太虚团队增益、莫问默认和莫问多装备，每种配置分别执行普通批跑与完整八项收益。每个负载运行 1,024 场、300 秒、4 个工作线程，训练种子为 713。GCC 用原子计数收集多线程训练数据。

随后脚本在同一构建目录切换为 `USE` 并重新编译。缺少 profile 或 GCC 检出控制流不匹配会导致编译失败。生成的程序用相同种子重放训练负载，核对结果后打印桌面程序路径。直接运行该程序即可打开正常的工作台。修改热点代码或更换 GCC 版本后，可重新执行脚本生成匹配的 profile。

以下命令同时保留普通版、运行对照并导出结果。

```sh
python tools/desktop_pgo.py --benchmark --workers 20 --iterations 100000 --rounds 4
```

两个程序都使用桌面默认宏和 `BatchWorker`。计时覆盖 worker 内的配置准备、战斗、技能统计和收益归约。每轮交替安排普通版与优化版的先后顺序，测量种子为 42。完整收益使用桌面默认的同数值模式，每项增加 100 点；每个输入批次计算基准伤害和全部八项收益。

脚本用各技能累计伤害之和核对整批的整数总伤害，并精确比较场数、基础校验值、最低与最高伤害及八项收益对应的名称、增量和校验值。校验值在 JSON 中使用十进制字符串，以保留全部 64 位。构建目录下的 `desktop-pgo-results.json` 包含可执行文件哈希、逐轮耗时、校验值和中位数。

`--build-dir` 可指定独立的构建目录，`--jobs` 控制并行编译任务数。已有 Qt 安装可通过 `--cmake-arg=-DQt6_DIR=...` 传给 CMake。手动编排时，在同一个 Release 构建目录中使用 `-DJX3DPS_DESKTOP_PGO=GENERATE` 和 `-DJX3DPS_DESKTOP_PGO=USE` 切换阶段；训练与计时入口由 `-DJX3DPS_DESKTOP_WORKLOAD=ON` 启用。

2026-11-18 在 i7-12700、Windows、GCC 16.2 Release 上按上述命令测得以下四轮中位数，单位为秒。每格为普通版 → PGO 版。

| 配置 | 普通批跑 | 完整八项收益 |
|---|---:|---:|
| 太虚 · 默认 | 0.578 → 0.476 | 1.854 → 1.541 |
| 太虚 · 团队增益 | 1.188 → 1.035 | 6.932 → 3.694 |
| 莫问 · 默认 | 0.517 → 0.391 | 1.641 → 1.279 |
| 莫问 · 多装备 | 1.090 → 0.978 | 5.037 → 3.266 |

64 个实测批次的总伤害及基础校验值均通过对照，32 个完整收益批次的八项校验值也全部一致。收入上表的每个完整收益批次包含 10 万场基准、10 万场会心重跑、10 万场加速重跑，以及六项伤害回放。

已有训练数据时，可以单独运行留出宏验收。

```sh
python tools/desktop_pgo.py --holdout --workers 20 --iterations 100000 --rounds 4
```

`--holdout` 从现有构建目录读取 `batch_worker.cpp.gcda`，只构建 `OFF` 和 `USE`。脚本验证运行前后的 profile SHA-256 相同，按“配置、宏、模式”逐项核对结果，并将每份宏的 SHA-256、每轮耗时和完整校验值写入独立的 `desktop-pgo-holdout.json`。常规训练只使用桌面默认宏。

验收集包含[七份独立的宏文件](../tests/performance/pgo_holdout)，共 13 个配置与宏的组合。

| 宏的行为 | 太虚 | 莫问 |
|---|---|---|
| 长条件链 | 两种配置，气点、生命、资源和上一技能参与 AND/OR 决策 | 两种配置，额外覆盖羽的充能及曲风条件 |
| 顺序施放 | 两种配置，先依次执行碎星辰、生太极、人剑合一和紫气，再进入常规循环 | 两种配置，先依次释放疏影、商、角和羽，再进入常规循环 |
| 强制打断 | — | 两种配置，以 `/fcast` 打断变徵引导，随后回到施放循环 |
| DOT 维持 | 团队增益配置带叠刃奇穴，按剩余时间补叠刃 | 两种配置，分别按商和角的剩余时间刷新双 DOT |

太虚默认配置没有叠刃奇穴，太虚的这两套配置也没有会自然开启引导的施放循环；表中的打断专项使用莫问的实际引导。顺序宏的 `/scast` 只在起手成功释放一次，后续按 `/cast` 优先级循环。

2026-11-18 使用原训练 profile（SHA-256 `0683b482891fa6442e649537470af97dd46d8d0de091d9ffd36b373aa735c08a`）完成四轮验收。26 个组合的中位数全部加快，普通批跑省时 7.7%～29.3%，完整收益省时 10.9%～29.2%。104 对计时中有两对单轮回退：团队增益太虚的长条件链普通批跑一次慢 1.6%，多装备莫问的双 DOT 完整收益一次慢 5.5%。208 个批次的整数总伤害、基础校验值及对应收益校验值全部通过比对。
