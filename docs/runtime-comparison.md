# 第四版与新版战斗模拟对照（2026-11-19）

第四版基线为 `131d2d1`，新版为 `1d2adee`。在两版共同支持的输入上，以逐帧为基准，90 对战斗的成功施放序列和总伤害一致。直接载入旧版默认配置、改变旧版精度、逐行比较原始报表，均可发现差异。

## 逐击核对

每场 300 秒，旧版 `FramePrecision=1`、零延迟，固定目标和初始资源。记录旧引擎实际使用的会心及触发随机数，交给新版按类型和顺序消费，90 对均无剩余随机数。只在诊断程序中记录宏实际施放的技能和帧，另取伤害事件核对帧、名称、伤害和命中结果。重复命中保留计数；破招、武器和 DOT 的历史别名按比较脚本归一。原生随机数性能测试另行运行。

太虚覆盖起始气点 0/10 和自然回气相位 0/7/15，每组合重新录制两次；莫问每种宏录制六场。莫问循环采用对照用全会心配置。全部 **29,760 次施放、60,964 次正伤害事件**均完成核对。莫问循环六场的同帧事件集合完全一致，列表顺序有差异。一场在第 32 帧，新旧列表首先给出的影子伤害分别为 8,326 和 8,720，本帧随后均能找到对应项。

旧伤害汇总和新版技能统计也有不同的列名和计数范围。一场太虚循环，两边均成功施放 424 次、产生 656 次正伤害命中；新版另外列出 5 次零伤害紫气东来，旧伤害汇总没有这一行。旧表的“破”和新表的“破招”对应相同效果。此次验证涵盖列出的心法、宏、装备和属性组合，尚未覆盖全部配置或跨版全部属性收益。

## 默认设置下的反例

第四版窗口初始化 `FramePrecision=24`，打开逐帧模式后为 1。用冷却宏、初始气点 0、固定回气相位 0、会心等级和浮动武器伤害均为 0 实测：

|版本与设置|三柴命中|三环命中|八荒命中|正伤害事件|总伤害|
|---|---:|---:|---:|---:|---:|
|第四版，24 帧|219|375|50|644|5,907,466|
|第四版，1 帧|219|414|48|681|6,373,488|
|新版，事件驱动|219|414|48|681|6,373,488|

旧界面自带太虚宏还会执行 `/cast 宏·紫气宏`，在多个命名宏间切换。把原始第一段送入新版编译器会报告 `unknown or out-of-range name: 宏·紫气宏`。这属于输入兼容性差异。独立启动的两代程序也使用不同的原生随机源，同一组面板属性不足以保证同一场获得相同会心序列。

## 核心耗时与原因

i7-12700、Windows x64、GCC 16.2 Release，单工作线程、关闭热点。每轮预热 8 场再测 200 场，各 3 轮交替引擎顺序取中位数。单位均为微秒/场。旧版以内层 `Simulate` 汇总出实际总伤害，新版复用 `Simulation` 并结算实际总伤害。计时不包括桌面渲染、配置解析、跨线程排队、JSON 输出或完整八项属性收益。在线程池上的整批提速需要单独测量。

|宏和配置|第四版 1 帧|第四版 24 帧|新版|相对第四版 1 帧|
|---|---:|---:|---:|---:|
|太虚循环|3,951.4|1,329.7|38.7|102.1 倍|
|太虚循环 + 叠刃 + 四项团队增益|5,121.3|1,660.7|51.8|98.9 倍|
|莫问循环|7,538.1|3,458.3|62.8|120.0 倍|

1. 第四版 `UpdateKeyFrameSequence` 要更新队列中的技能与增益。施放后还会遍历剩余事件、检查下次时间、重新插入链表。旧桌面太虚默认循环（零延迟、1,200 场、19 个工作线程、963 个样本）中，重查与重排占 **40.7%**，推进已有关键帧占 **5.4%**。新版的绝对到期时间堆只调整受影响的定时器，再跳到下一事件或宏时间条件边界。
2. 第四版在命中路径计算多套属性扰动的伤害，并写入多层统计表。仅屏蔽旧引擎内嵌的这些额外计算，太虚的 1 帧耗时从 3,951.4 降到 3,244.0 µs（−17.9%），团队配置从 5,121.3 降到 4,149.0 µs（−19.0%）。新版记录命中意图，延后结算；需要伤害类属性收益时复用基准命中统计。这一对照只量到了该项的部分成本。
3. 第四版每场克隆角色、复制宏与事件列表、生成关键帧并逐技能合并嵌套统计。新版复用工作线程的状态、数组和日志，宏执行使用编译后的槽位与条件，并可在读条、引导或公共冷却期间跳过不可能的尝试。前两项有采样或独立对照，这些复用与宏优化没有在本次实验中逐项关闭，不能给每项分配一个独立倍数。

## 第四版热点入口和验证

选择心法，在“输出”勾选“采集性能热点”，再开始模拟。结束后自动显示整批火焰图，点击色块可下钻，“查看热点”可重新打开。火焰图按工作线程执行期间的周期性观测统计，含未单独标记的子调用及线程调度等待。界面另列批跑墙钟时间和线程累计用时。未开启时不会创建采样线程或输出热点数据。

用同一确定性三柴配置通过真实桌面开始按钮运行：1,200 场基准 + 1,200 场加速重跑，19 个工作线程。关闭时无 `PerformanceHotspots` 字段；开启时报告 2,400 场。去掉该诊断字段后，两份 JSON 完全相等，包括各项 `Stats` 和每场 `DamageList`。
