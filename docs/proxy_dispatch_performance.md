# Proxy 分派与单场战斗耗时

生产引擎的 `Session` 使用虚函数。桌面宏编辑器直接保存可选的 `JX3MacroSyntaxChecker`，工作台注入的校验回调优先。Proxy 4.1.0 用于性能项目中需混合存放和遍历的对象，例如 Buff、冷却、气血和内力条件。这些小条件用 `make_proxy_inplace` 内联存放，超过内联容量会在编译时被发现。

下表记录了选择会话实现时的对照实验。2026-11-20，在 i7-12700、Windows x64、GCC 16.2 Release 上，将提交 `ba323e2` 的虚会话接口与实验版 Proxy 会话对照。两份原生引擎使用相同的 JSON 头文件、`-O3 -DNDEBUG` 和 C ABI。这里测的是 Web Worker 使用的分段批跑接口在原生机器上的表现。浏览器 WASM 另做结果校验。

## 整批耗时

使用 `start`、`next`，固定逻辑 CPU 2。每种配置读取引擎内置中文宏，种子 42，每场模拟 300 秒。每个版本先预热 256 场，再分别测六轮，每轮十万场，交替执行顺序。计时包含会话创建、批跑、最终技能统计、读取 JSON 和会话销毁。

| 配置 | 虚函数中位耗时 | Proxy 中位耗时 | 中位耗时变化 | Proxy 较快轮数 |
| --- | ---: | ---: | ---: | ---: |
| 太虚默认 | 4.204 s | 4.241 s | +0.88% | 1/6 |
| 太虚团队增益 | 9.751 s | 10.316 s | +5.80% | 2/6 |
| 莫问默认 | 4.143 s | 4.253 s | +2.68% | 0/6 |
| 莫问多装备 | 9.623 s | 9.580 s | −0.45% | 3/6 |

表中正数表示耗时增加，百分比按两组中位数之比计算。莫问默认六轮都慢，逐对增加 1.41% 至 3.76%。四种配置的完整批跑结果逐轮相同，包括每个技能的次数、伤害和会心数。两版按相同操作单步执行四种配置，57,822 次调试步的返回状态也逐步一致。

## 分派发生在哪里

- 在固定四个条件的解释器微基准中，一轮遍历从 5.136 ns 降到 4.788 ns，十组配对均更快。旧版逐个访问堆上的多态对象，新版将小条件对象内联到 Proxy 容器中。这个实验同时改变了对象布局与分派方式。
- `Battle::advance` 每次最多执行 128 场。十万场只经过 782 次会话推进分派，技能、定时器和逐击伤害仍由模板实例执行。在这套 x64 构建中，Proxy 句柄占 24 字节，原所有权指针占 8 字节。太虚和莫问会话对象分别占 25,568 和 1,912 字节，两者仍使用堆分配。整批计时无法把这些百分比差异单独归因于一次间接调用。
- 桌面原生 `batch` 直接调用 `nativeBatch`。另用 20 线程各跑十万场、每版四轮，核对了校验值和逐技能汇总。这条路径绕过会话分派。
- 编辑器内置检查器用同一份含两种错误的宏反复执行 `CheckSyntax`，比较十组，每组 2,000 次。单次中位耗时从 133.40 µs 变为 134.16 µs，错误位置、级别与消息摘要相同。工作台注入自定义检查器时走已有的回调路径。

## 小对象遍历与正式宏引擎

在当前的 `Interpreter` 基准中，Buff、冷却、内力和气血条件共用一段遍历代码。堆上的虚对象遍历四项耗时 5.058 ns，内联 Proxy 耗时 4.662 ns。八组交替测试中 Proxy 均更快，按中位数计算耗时减少 7.8%。

正式宏引擎将条件编译成连续的 24 字节指令，指令同时保存比较值和两个短路跳转目标。为检验这个场景，另建实验版，在快速执行路径上将 11 种取值操作分别编译为内联 Proxy，每条占 32 字节。两个版本均使用虚函数会话。每轮跑 12,500 场，每场 300 秒，种子 42，每种配置和宏各做八轮配对，轮换执行顺序。下表是每轮耗时变化百分比的中位数，正数表示实验版更慢。

| 配置 | 默认宏 | 长条件链验收宏 |
| --- | ---: | ---: |
| 太虚默认 | −0.74% | −0.94% |
| 太虚团队增益 | +1.82% | +0.98% |
| 莫问默认 | −0.78% | +0.48% |
| 莫问多装备 | +0.99% | +0.15% |

八种组合每轮的完整结果均一致，包括总伤害校验值、逐技能次数与伤害。太虚团队增益搭配默认宏时，Proxy 八轮都更慢。正式执行器继续使用 24 字节的条件指令。

## 复测

四个小条件的对照保存在 `performance/interpreter` 中。两个测试按相同顺序调用相同的条件实现，分别用堆上的虚对象和连续内联的 Proxy 存储。对象构造在计时循环外。

```sh
git submodule update --init 3rd/json 3rd/proxy 3rd/benchmark 3rd/googletest
cmake -S . -B build-perf -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_APP=OFF -DBUILD_PERFORMANCE=ON
cmake --build build-perf --target Interpreter
build-perf/bin/Interpreter --benchmark_filter="^BM_(Virtual|Proxy)$" --benchmark_repetitions=8
```

整场对照可用同一编译器分别构建基线与待测版本的 Release 共享引擎，设置 `JX3DPS_SHARED_ENGINE=ON`。在同一固定核心运行以下命令。脚本输出每轮原始秒数、配对节省比例、总伤害和校验值，任一完整结果不同会退出。[对照脚本](../tests/performance/compare_sessions.py)

```sh
python tests/performance/compare_sessions.py BEFORE_LIBRARY AFTER_LIBRARY --iterations 100000 --repeats 6
```
